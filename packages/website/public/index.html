Security Whitepaper & Threat Model

Engineered to the standard of "trust this with bank passwords."

1. Two-Key Envelope Key Hierarchy

When you create a Kloak vault, a cryptographically random 256-bit Vault Key (VK) is generated. A Key Wrapping Key (KWK) is derived from your master password using PBKDF2-SHA256 (600,000 iterations) with a 256-bit random salt. The KWK wraps the VK using AES-256-GCM. When changing passwords, only the VK envelope is re-encrypted—preventing payload corruption.

2. In-Memory Hygiene & Zeroization

Decrypted secrets and unwrapped keys are strictly scoped. When the vault auto-locks on idle timeout (default 5m) or upon manual lock, the active memory buffers are explicitly wiped with zeros (zeroizeBuffer), defeating forensic memory scrapers.

3. Phishing-Resistant Autofill Domain Matching

The browser extension and native engine extract effective top-level domains (eTLD+1) before injecting credentials, strictly preventing lookalike domain and subdomain impersonation attacks (e.g. github.com.evil-attacker.com).
