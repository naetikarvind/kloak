Summary of Our Privacy Commitments

Kloak was created on the fundamental principle of absolute local-first security and zero-knowledge data privacy. We do not operate user accounts, we do not operate remote databases for your passwords, we do not run tracking or analytics, and we will never monetize, sell, or disclose your personal data.

🔒 100% On-Device Vault All credentials and 2FA secrets are encrypted locally with AES-256-GCM. Zero cloud storage.
🚫 No Remote Code 100% of extension code is statically bundled at build time. No scripts or CDNs are loaded at runtime.
🌐 Zero Tracking & Ads No analytics, no telemetry, no tracking cookies, and zero advertising profiling.
💻 Local IPC Only Extension communicates exclusively with the local native desktop daemon (app.kloak.native).

Chrome Web Store User Data Privacy Compliance

This document strictly satisfies the Google Chrome Web Store Developer Program Policies regarding User Data Privacy (including the four required sections: User Data Collection, User Data Handling, User Data Storage, and User Data Sharing).

1 Scope & Single Purpose Specification

This Privacy Policy applies to the Kloak Password Manager software ecosystem, specifically:

  • Kloak Password Manager Chrome Extension (Chrome Web Store Extension ID: hajgkgmajepndkhjhcgjenjnfojlphod);
  • Kloak Password Manager Native macOS Application;
  • Kloak Raycast Extension;
  • Official open-source repositories and documentation hosted under github.com/naetikarvind/kloak.
Single Purpose Declaration: The single purpose of the Kloak Chrome Extension is to securely autofill login credentials, passkeys, and two-factor authentication (TOTP) codes from the user's local, encrypted vault directly into website login forms upon user request. All features—including field badge overlays, credential lookups, strong password generation, and domain phishing verification—exist solely to facilitate and protect this singular credential filling flow.

2 User Data Collection

In accordance with Chrome Web Store User Data policies, this section explicitly discloses every category of data accessed, handled, or collected by the extension:

2.1 Authentication Information (Credentials & Secrets)

What is accessed: Usernames, login email addresses, account passwords, passkeys, Time-based One-Time Password (TOTP) secret keys, security notes, and optional payment card entries.

Source & Method of Collection: Provided directly and voluntarily by the user (either manually entered, imported from a previous password manager file, or saved when logging into a website).

Collection Scope: The extension queries your credentials from the local desktop vault only when you navigate to a matching domain or click the extension popup/side-panel. Authentication information is never uploaded, synced, or transmitted to any remote cloud server.

2.2 Website Content & Input Fields

What is accessed: Form input elements (specifically HTML <input type="password">, <input type="email">, <input type="text">, and two-factor authentication fields) on web pages visited by the user.

Source & Method of Collection: Detected locally within the browser page Document Object Model (DOM) by the extension's content script (content.js).

Collection Scope: The content script inspects input attributes purely to display the Kloak autofill badge inside the field and insert the requested login credentials upon explicit user action. No page body text, personal messages, or unrelated webpage content is collected, copied, or recorded.

2.3 Web History & Active Tab Domain (URLs)

What is accessed: The active tab's domain name (e.g. github.com) accessed via the tabs and activeTab browser APIs.

Source & Method of Collection: Read in transient, volatile local memory when a tab is loaded or focused.

Collection Scope: The domain hostname is evaluated solely to search the local vault for matching logins and verify domain legitimacy against phishing attacks. Your browsing history is never recorded, never logged to disk, and never sent across the internet.

2.4 Financial & Payment Information (Optional)

What is accessed: Credit card numbers, expiration dates, and cardholder names that you voluntarily save into your local vault.

Collection Scope: Handled with identical zero-knowledge AES-256-GCM encryption on your local disk. Filled only upon your affirmative 1-click confirmation on checkout forms.

2.5 User Settings & Technical Preferences

What is accessed: Extension display theme (dark/light), auto-lock duration, clipboard auto-clear timeout, and active display modes.

Storage Method: Saved in the browser's local sandbox via chrome.storage.local.

2.6 Categories of User Data That Are NEVER Collected

To ensure complete clarity, Kloak affirms that it does NOT collect, read, or process:

  • No Personal Communications: We do not read or access emails, chat messages, or document contents.
  • No Geolocation Data: We do not request or track GPS, IP geolocation, or physical location.
  • No Health or Medical Information: We do not collect health or medical data.
  • No Device Identifiers: We do not collect MAC addresses, hardware UUIDs, or serial numbers.
  • No Browsing History Logs: We do not maintain a history of visited URLs.
  • No Telemetry or Analytics: We do not use Google Analytics, tracking beacons, or telemetry scripts.

3 User Data Handling and Use

Google Chrome Web Store policies require an unambiguous explanation of how collected user data is handled, processed, and utilized.

3.1 Purpose-Bound Processing

Every piece of user data accessed by Kloak is handled solely to execute the application's core functionality:

  • Credential Autofill: Usernames and passwords stored in your local vault are injected into corresponding login fields when you click the field badge or toolbar popup.
  • 2FA Verification: Stored TOTP secrets are processed locally to compute time-synchronized 6-digit one-time codes and fill verification prompts.
  • Anti-Phishing Verification: The active tab domain is matched against your saved logins to ensure credentials are never exposed to counterfeit, typosquatted, or spoofed lookalike websites.
  • Secure Password Generation: High-entropy cryptographic random numbers are generated on-demand to create strong passwords for registration forms.
Mandatory Chrome Web Store Policy Affirmations:
  • We do NOT use or transfer user data for purposes unrelated to the extension's core single purpose.
  • We do NOT use or transfer user data to serve personalized, targeted, or behavioral advertisements.
  • We do NOT use or transfer user data to determine creditworthiness or for lending purposes.
  • We do NOT use user data for surveillance, user tracking, or data profiling.

4 User Data Storage, Retention, and Security Safeguards

Transparency regarding where and how data is stored, how long it is retained, and how it is secured is mandatory under Chrome Web Store policies:

4.1 Storage Location & Local-First Architecture

All user credentials, passwords, passkeys, notes, and 2FA secrets are stored 100% locally on your own computer:

  • Local Vault File: Persisted in an encrypted binary file located on your device at ~/.kloak/vault.kloak.
  • Local Extension Settings: Non-sensitive UI preferences are kept in browser-isolated local storage (chrome.storage.local).
  • Zero Cloud Databases: Kloak operates no remote user accounts, no cloud sync servers, and no centralized databases. Your data never resides on our infrastructure because we do not operate any storage servers.
4.2 Encryption & Security Measures

Your data is protected by industry-standard cryptographic primitives:

  • Authenticated Encryption: The local vault is encrypted using AES-256-GCM (Galois/Counter Mode), guaranteeing both confidentiality and cryptographic integrity.
  • Key Derivation: Master keys are derived using Argon2id and PBKDF2-HMAC-SHA256 with high work factors to protect against brute-force attacks.
  • Hardware Protection: On macOS, master keys are enveloped by the Apple Secure Enclave and protected by Touch ID biometric authentication.
  • Local Inter-Process Communication (IPC): Communication between the Chrome extension and desktop application occurs strictly over local OS native messaging pipes (app.kloak.native) and loopback socket (127.0.0.1:53152). It never traverses the external network.
4.3 Data Retention & Deletion Procedures

Because all data is stored on your device, retention is entirely under your control:

  • Retention Schedule: Credentials remain stored locally until you choose to edit or delete them. Active tab URLs inspected in memory are strictly ephemeral and are discarded immediately upon navigation or tab close.
  • Individual Item Deletion: You can permanently delete individual credentials or records at any time from the extension side-panel or desktop app.
  • Full Vault Purge: You can completely wipe the local vault (~/.kloak) via the Kloak Settings menu or Developer Mode reset.
  • Extension Uninstallation: Uninstalling the extension immediately purges all data stored in chrome.storage.local.

Google Chrome Web Store program policies strictly prohibit omission of data sharing disclosures:

Absolute Prohibition on Selling & Sharing:
  • We do NOT sell, rent, lease, license, or monetize user data to third parties under any circumstances.
  • We do NOT share, transfer, or disclose user data to third parties, data brokers, advertising networks, or analytics providers.
  • We do NOT transmit passwords, credentials, usernames, or vault contents over the public internet.
5.1 Read-Only Phishing Threat Lookups

To protect users from fraudulent lookalike domains and brand impersonation attacks, the desktop application may perform read-only queries against public domain infrastructure:

  • DNS Resolution: Standard DNS-over-HTTPS queries via Cloudflare Public DNS (1.1.1.1) to verify domain records;
  • Domain Age (RDAP): Public Registration Data Access Protocol (RDAP) queries to inspect domain registration age (newly registered domains carry high phishing risk).

Strict Safeguard: These lookups query only public domain hostnames (e.g. paypal.com). They never transmit user credentials, passwords, usernames, IP addresses, or personal information.

6 Browser Permissions & Technical Justification

Every browser permission declared in Kloak's Manifest V3 manifest is strictly required for its single purpose:

Permission Purpose in Kloak Privacy Safeguard
<all_urls> (host_permissions) Enables the autofill content script to detect username, password, and 2FA input fields across arbitrary websites visited by the user. Runs isolated in DOM. No webpage text or content is read or transmitted unless the user explicitly clicks autofill on that page.
tabs Reads the active tab's domain name to query your local vault for matching logins and verify the domain against phishing lookalikes. Evaluated strictly in volatile local memory. Browsing history is never stored, logged, or sent over any network.
activeTab Grants temporary script execution authority to insert credentials when the user clicks the autofill button or popup action. Restricted to explicit user interaction. Cannot activate silently in the background.
nativeMessaging Connects the browser extension to the local Kloak desktop daemon (app.kloak.native) running on your Mac. Operates exclusively via local OS pipes/stdin-stdout. No internet connection is created.
sidePanel Allows users to open and view their vault records in Chrome's native Side Panel alongside web pages. Rendered entirely offline from local extension assets.
clipboardWrite Allows users to copy generated passwords, usernames, and 2FA TOTP codes to their system clipboard. Write-only access; the extension cannot read or inspect preexisting clipboard contents.
storage Saves extension UI preferences, lock timers, and display modes. Uses isolated, local browser storage (chrome.storage.local) without remote cloud sync.

8 User Rights & Regulatory Compliance

Because Kloak stores data strictly on your device, you have complete sovereignty over your data under international privacy frameworks:

  • GDPR (European Union): Kloak does not transmit or process personal data on remote servers. All processing occurs locally under the user's sole control. Users have absolute rights to access, export, and erase their data locally at any time.
  • CCPA / CPRA (California): We do not sell or share personal information as defined by California law. No personal information is retained or transferred for monetary or commercial consideration.
  • COPPA (Children's Privacy): Kloak does not knowingly collect personal information from children under 13. The application is completely local-first and does not operate accounts.

9 Strict Ban on Remote Code & Third-Party Libraries

In compliance with Google Manifest V3 security requirements:

  • No Remotely Hosted Code: The extension executes only statically bundled local code included in the verified Chrome Web Store package. It never loads scripts, styles, or WebAssembly from remote servers or CDNs.
  • Strict Content Security Policy (CSP): Disallows eval(), new Function(), and inline scripts.
  • No Telemetry SDKs: No third-party trackers, crash reporters, or advertising beacons are embedded.
